## 문제부터 시작해 봅시다

19강에서 상품 2,000개를 ScrollView로 만들었더니 첫 화면이 몇 초 걸렸습니다. FlatList로 바꾸자 화면이 바로 떴어요. 그런데 새로운 문제가 세 가지 생겼습니다.

1. 손가락으로 세게 튕겨 스크롤하면 잠깐 **하얀 빈칸**이 보입니다.
2. 목록 맨 위에 새 상품을 추가했더니, 사용자가 체크한 **체크 표시가 엉뚱한 상품으로** 옮겨 갔습니다.
3. 상품을 눌러 "선택됨" 색을 칠하게 했는데, State는 바뀌었는데도 **화면이 그대로**입니다.

세 버그 모두 FlatList를 빠르게 만들어 준 바로 그 장치, **가상화(virtualization)**에서 나옵니다.

## 비유: 도서관 열람실 책상

2,000쪽짜리 자료를 본다고 해 봅시다.

- **ScrollView 방식**: 2,000쪽을 전부 책상에 펼쳐 놓고 봅니다. 펼치는 데 오래 걸리고 책상(메모리)도 꽉 찹니다.
- **FlatList 방식**: 목차(data 배열)는 전부 가지고 있지만, 지금 보는 쪽 **앞뒤 몇십 쪽만** 책상에 펼칩니다. 앞으로 넘어가면 새로 서고에서 꺼내 펼치고, 멀어진 쪽은 다시 서고로 돌려보냅니다.
- 너무 빨리 넘기면 사서가 책을 가져오기 전에 그 자리에 도착합니다. 이때 잠깐 보이는 **빈 책상**이 빈칸입니다.

<Callout kind="limit" title="이 비유가 맞지 않는 지점">
서고에 돌려보낸 책은 다시 꺼내도 똑같지만, FlatList가 치운 행은 <strong>컴포넌트 인스턴스 자체가 사라집니다(언마운트)</strong>. 행 안에 둔 State(입력 중인 글, 펼침 여부)는 함께 사라지고, 다시 보일 때는 새로 만들어집니다. 그래서 오래 기억해야 할 값은 행이 아니라 목록 바깥(부모 State나 데이터)에 둬야 합니다.
</Callout>

## 정확한 정의

- **FlatList**: `VirtualizedList`를 기반으로 한 가상화 목록 컴포넌트입니다. 핵심 props는 세 가지예요.
  - `data`: 전체 배열
  - `renderItem({ item, index })`: 행 하나를 그리는 함수
  - `keyExtractor(item, index)`: 행의 고유 key를 정하는 함수
- **가상화(windowing)**: 현재 스크롤 위치 주변의 일정 범위, 즉 **창(window)**의 항목만 마운트하고, 창 밖 항목은 마운트하지 않거나 해제하는 기법입니다.
- **windowSize**: 창의 크기를 "뷰포트 높이" 단위로 정합니다. 1이 뷰포트 높이 하나입니다. 공식 문서 기준 기본값은 21로, 보이는 화면 1개에 위로 10화면, 아래로 10화면을 더한 크기입니다.
- **initialNumToRender**(기본 10): 첫 렌더에서 만드는 항목 수입니다.
- **maxToRenderPerBatch**(기본 10): 스크롤할 때 한 묶음(batch)으로 새로 만드는 항목 수입니다.
- **updateCellsBatchingPeriod**(기본 50ms): 묶음 사이의 간격입니다.
- **extraData**: FlatList는 props가 얕은 비교(shallow equal)로 같으면 다시 렌더하지 않습니다. `data` 말고 행 모양에 영향을 주는 값(선택된 id 등)이 있으면 이 prop으로 알려 줍니다.

## 왜 존재하는가

19강에서 본 대로 ScrollView는 자식을 전부 만듭니다. 항목이 n개면 첫 렌더 비용도 O(n), 메모리도 O(n)입니다. 그런데 휴대폰 화면에 동시에 보이는 행은 많아야 10개 안팎이에요. 2,000개 중 1,990개는 지금 당장 필요 없는데도 만들어지는 셈입니다.

가상화는 "보이지 않는 것은 만들지 않는다"는 아이디어로 비용을 **O(창 크기)**로 줄입니다. 데이터가 10개든 10만 개든 한 번에 만드는 행의 수는 거의 같아집니다. 대신 세 가지 대가가 따릅니다.
1. 행을 계속 만들고 지우는 일이 생깁니다.
2. 행의 높이를 미리 알 수 없어 측정해야 합니다.
3. 행의 정체성을 key로 관리해야 합니다.

## 예제 1 — 기본: 실제로 동작하는 피드

<div class="code-title"><span>Feed.js — 기본 예제</span><span class="badge real">그대로 실행 가능</span></div>

```jsx
import { memo, useCallback, useState } from 'react';
import { FlatList, View, Text, Pressable, StyleSheet } from 'react-native';

const ROW_HEIGHT = 72;
const makeItems = (from, count) =>
  Array.from({ length: count }, (_, i) => ({ id: String(from + i), title: `상품 ${from + i + 1}` }));

const Row = memo(function Row({ item, selected, onPress }) {
  return (
    <Pressable onPress={() => onPress(item.id)} style={[styles.row, selected && styles.selected]}>
      <Text style={styles.title}>{item.title}</Text>
    </Pressable>
  );
});

export default function Feed() {
  const [items, setItems] = useState(() => makeItems(0, 50));
  const [selectedId, setSelectedId] = useState(null);

  const renderItem = useCallback(
    ({ item }) => <Row item={item} selected={item.id === selectedId} onPress={setSelectedId} />,
    [selectedId],
  );

  return (
    <FlatList
      data={items}
      keyExtractor={(item) => item.id}
      renderItem={renderItem}
      extraData={selectedId}
      getItemLayout={(_, index) => ({ length: ROW_HEIGHT, offset: ROW_HEIGHT * index, index })}
      onEndReached={() => setItems((prev) => [...prev, ...makeItems(prev.length, 50)])}
      onEndReachedThreshold={0.5}
      ListEmptyComponent={<Text style={styles.empty}>상품이 없습니다</Text>}
    />
  );
}

const styles = StyleSheet.create({
  row: { height: ROW_HEIGHT, justifyContent: 'center', paddingHorizontal: 16, borderBottomWidth: StyleSheet.hairlineWidth, borderColor: '#dde2ee', backgroundColor: '#fff' },
  selected: { backgroundColor: '#e8eeff' },
  title: { fontSize: 16 },
  empty: { padding: 24, textAlign: 'center' },
});
```

## 내부 동작: 창이 움직이는 과정

1. **전체 데이터 보유** — `data` 배열 전체를 받습니다. 배열을 갖고 있는 것만으로는 화면 비용이 거의 들지 않습니다.
2. **첫 렌더** — 처음 `initialNumToRender`(10)개만 `renderItem`으로 만듭니다. 화면을 덮기에 충분하면 첫 화면이 빨리 뜹니다.
3. **창 계산** — 스크롤 위치(onScroll로 받음)와 뷰포트 높이로 창의 범위를 계산합니다. windowSize 21이면 보이는 화면 위아래로 10화면씩입니다.
4. **배치로 채우기** — 창 안에서 아직 없는 행을 보이는 곳 가까이부터 `maxToRenderPerBatch`(10)개씩, 약 50ms 간격으로 만듭니다. 한 번에 다 만들지 않는 이유는 JS 스레드를 오래 붙잡으면 터치 반응이 늦어지기 때문입니다.
5. **창 밖 해제** — 창을 벗어난 행은 언마운트되고, 그 행의 State도 사라집니다. 그 자리에는 높이만 차지하는 빈 공간이 남아 전체 스크롤 길이는 유지됩니다.
6. **측정** — 행 높이를 모르면 레이아웃 후에 측정해서 위치를 기록합니다. `getItemLayout`이 있으면 이 단계를 건너뜁니다.

**빈칸이 생기는 이유**는 스크롤과 행 생성이 서로 다른 곳에서 일어나기 때문입니다. 스크롤은 네이티브에서 즉시 움직이고, 행 생성은 JS가 배치 단위로 따라옵니다. 손가락이 창보다 빨리 움직이면 아직 만들지 못한 자리가 잠깐 비어 보입니다.

## 실습 1 — 가상화 창과 빈칸

세 가지를 비교해 보세요.
- **FlatList (기본값)**: 처음 10개를 만든 뒤, 창이 얼마나 커질 때까지 배치가 이어지는지 봅니다.
- 🐞 **windowSize={1}**: 마운트되는 행 수는 줄지만, 빠르게 스크롤하면 빈칸이 생깁니다.

"빠른 스크롤로 이동할 행"을 100 이상으로 올리면 기본값 FlatList에서도 빈칸이 생깁니다. 창이 아래로 약 80행까지만 미리 만들어 두기 때문입니다.

## 예제 2 — 함정: 눌러도 색이 안 바뀌는 목록

<div class="code-title"><span>Pick.js — 함정 예제</span><span class="badge real">그대로 실행 가능 (버그 재현)</span></div>

```jsx
import { useState } from 'react';
import { FlatList, Pressable, Text } from 'react-native';

const DATA = [{ id: 'a', name: '사과' }, { id: 'b', name: '배' }, { id: 'c', name: '귤' }];

export default function Pick() {
  const [selectedId, setSelectedId] = useState(null);
  return (
    <FlatList
      data={DATA}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <Pressable onPress={() => setSelectedId(item.id)}>
          <Text style={{ padding: 16, fontWeight: item.id === selectedId ? '700' : '400' }}>{item.name}</Text>
        </Pressable>
      )}
    />
  );
}
```

<CodeWalk items={[
  ['10', 'data={DATA}', "DATA는 컴포넌트 밖의 상수라 렌더마다 같은 배열(같은 참조)입니다."],
  ['12–16', 'renderItem={({ item }) => ...}', "행의 굵기가 selectedId에 따라 달라집니다. 그런데 selectedId는 data 안에 없습니다."],
  ['13', 'setSelectedId(item.id)', "State는 바뀌고 Pick은 다시 렌더합니다. 하지만 FlatList 입장에서 data가 같은 참조이면 '목록이 바뀌지 않았다'고 판단해 행을 다시 그리지 않을 수 있습니다."],

FlatList는 PureComponent처럼 props를 얕게 비교합니다. `data`가 같은 참조로 들어오면 행을 다시 렌더하지 않을 수 있어요. 해결은 행 모양에 영향을 주는 바깥 값을 알려 주는 것입니다.

```jsx
<FlatList data={DATA} extraData={selectedId} /* ... */ />
```

또는 선택 여부를 data 안에 넣어 **새 배열**로 바꾸는 방법도 있습니다. 예: `setItems(prev => prev.map(...))`.

## 경계와 실패: 실제로 만나는 문제들

**1) key가 없거나 중복**

<Callout kind="error" title="실제 경고 메시지">
<code>VirtualizedList: missing keys for items, make sure to specify a key or id property on each item or provide a custom keyExtractor.</code>
</Callout>

keyExtractor가 없으면 FlatList는 `item.key`, 그다음 `item.id`를 쓰고, 둘 다 없으면 index로 대신합니다. 중복된 key는 React가 행을 구분하지 못하게 만들어, 행이 사라지거나 뒤섞입니다.

**2) index를 key로 사용** — 경고는 사라지지만 더 찾기 어려운 버그가 생깁니다. 아래 실습에서 직접 확인하세요.

<ListKeysLab />

**3) 행 안의 State가 사라짐** — 창 밖으로 나간 행은 언마운트됩니다. 행 안 TextInput에 쓰던 글이나 "더보기" 펼침 상태는 스크롤해서 돌아오면 초기화됩니다. 이런 값은 부모 State에 id별로 보관하세요. 예: `const [drafts, setDrafts] = useState({})`.

**4) 느린 행**

<Callout kind="error" title="실제 경고 메시지">
<code>VirtualizedList: You have a large list that is slow to update - make sure your renderItem function renders components that follow React performance best practices like PureComponent, shouldComponentUpdate, etc.</code>
</Callout>

행이 무겁거나, 매 렌더마다 모든 행이 다시 그려질 때 나옵니다. 해결 방법은 세 가지입니다.
- 행을 `memo`로 감쌉니다.
- `renderItem`을 `useCallback`으로 고정합니다.
- 이미지는 썸네일 크기로 씁니다.

**5) onEndReached가 여러 번 호출됨** — 데이터가 도착하기 전에 끝 근처에서 스크롤이 계속되면 같은 페이지를 중복 요청할 수 있습니다. `loading` 플래그로 진행 중인 요청을 막습니다.

**6) ScrollView 안에 FlatList 중첩** — 19강의 경고와 같습니다. 바깥 ScrollView가 FlatList를 끝까지 늘려서 가상화가 꺼집니다.

## 비교와 트레이드오프

| 설정·선택 | 올리면 | 내리면 |
|---|---|---|
| `windowSize` | 빈칸 감소, 메모리 증가 | 메모리 절약, 빈칸 증가 |
| `maxToRenderPerBatch` | 채우는 속도 증가(빈칸 감소), 한 번에 JS를 오래 점유해 터치 반응 저하 | 반응성 좋음, 빈칸 증가 |
| `initialNumToRender` | 첫 화면이 비지 않음, 첫 렌더 느려짐 | 첫 렌더 빠름, 화면을 다 못 덮으면 빈칸 |
| `getItemLayout` | (고정 높이일 때) 측정 생략, scrollToIndex 가능 | 행 높이가 다르면 쓸 수 없음 |

| 목록 구현 | 핵심 방식 | 장점 | 단점 |
|---|---|---|---|
| `ScrollView` + map | 전부 생성 | 단순, 빈칸 없음, State 유지 | 첫 렌더·메모리 O(n) |
| `FlatList` | 창 밖 언마운트 | 기본 제공, 대량 데이터 처리 | 빈칸, 행 State 소실, 튜닝 필요 |
| `SectionList` | FlatList + 구역 | 그룹 헤더 기본 제공 | FlatList와 같은 주의점 |
| 재활용(recycling) 목록 (예: Shopify FlashList, 외부 라이브러리) | 창 밖 행을 버리지 않고 새 데이터로 다시 씀 | 생성·해제 비용 감소 | 행 State가 다른 항목에 남지 않도록 더 주의해야 함 |

## 실무에서는

- **id는 서버가 준 고유값**을 씁니다. 화면에서 만든 index나 `Math.random()`은 렌더마다 바뀌거나 위치에 묶이므로 key로 쓰면 안 됩니다.
- **행 컴포넌트는 `memo`, `renderItem`은 `useCallback`**으로 감싸는 것이 기본 습관입니다. 행에 넘기는 콜백도 안정적인 참조여야 합니다. 예제 1에서 `onPress={setSelectedId}`가 그런 경우입니다.
- **고정 높이면 `getItemLayout`**을 넣습니다. "특정 항목으로 이동", "맨 위로" 기능도 안정적으로 동작합니다.
- **채팅**은 `inverted`로 아래부터 쌓고, **당겨서 새로고침**은 `refreshing` + `onRefresh`로 만듭니다.
- 성능 문제는 추측하지 말고 측정합니다. React Native DevTools의 프로파일러로 어떤 행이 왜 다시 렌더되는지 확인한 다음 위 설정을 조정하세요.
