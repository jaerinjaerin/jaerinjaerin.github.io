스택(Stack): 마지막에 넣은 것을 먼저 꺼내는 자료구조

이론 → 실제 조작 → 내부 배열 관찰 → 예외 처리 → 결과 예측

① 왜 스택이 필요할까요?

책을 쌓으면 맨 위 책을 먼저 꺼내기 쉽습니다. 프로그램도 최근에 저장한 데이터를 먼저 처리해야 할 때가 있습니다. 대표적인 예는 함수 호출 관리, 뒤로 가기, 실행 취소입니다.

② 정확한 정의

스택(Stack)은 자료를 한쪽 끝인 TOP에서만 삽입하고 제거하는 선형 자료구조입니다. LIFO(Last In, First Out) 규칙을 따릅니다. 즉 마지막으로 들어온 원소가 가장 먼저 나갑니다.

③ 내부 동작

PUSH(x)는 TOP 위에 값을 추가하고, POP()은 TOP 값을 반환하면서 제거합니다. PEEK()는 TOP을 제거하지 않고 확인합니다. 빈 스택에서 POP을 시도하면 언더플로(underflow)가 발생합니다.

배열을 이용한 일반적인 구현에서 PUSH와 POP은 끝부분만 사용하므로 평균적으로 O(1) 시간에 처리할 수 있습니다. 단, 동적 배열이 확장될 때 PUSH의 개별 수행 시간은 O(n)이 될 수 있습니다.

④ JavaScript 코드 분석

const stack = [];
stack.push(10); // [10]
stack.push(20); // [10,20]
const top = stack.pop(); // 20
// stack === [10]

push는 배열 끝에 요소를 추가하고, pop은 배열 끝 요소를 꺼냅니다. 실습 화면에서는 스택의 바닥을 아래에, TOP을 위에 그립니다.

⑤ 오류와 응용

스택이 비었는데 POP을 실행하는 잘못된 동작을 예방하려면 먼저 stack.length를 검사해야 합니다. 실제 프로그램의 호출 스택과 교육용 배열 스택은 원리가 유사하지만 완전히 같은 구현은 아닙니다.

이 실습은 실제 프로세스 메모리를 조작하지 않는 교육용 JavaScript 시뮬레이터입니다.
